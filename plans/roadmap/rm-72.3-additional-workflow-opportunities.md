## Gaps (where expansion actually helps)

1. **Catalog events without a reference graph** — 16 apps publish [domain events](../../docs/platform/lab-domain-events.md); demo seeds cover mainly CRM, time/expense approvals, one poll moment, webhooks, and Quarks. Most portfolio events are **catalog-only** (authors see triggers in Studio but no copy-paste graph).
2. **Step kinds with weak teaching coverage** — `comms_system_dm_payload_user` appears only in the webhook-loop demo; `rule_ref`, `publish_event` chains, `switch_condition`, and **scheduled triggers** are underrepresented in seeds vs what the runner already supports.
3. **Notify vs toast vs DM** — product has three channels; only two patterns are exercised end-to-end (bell notify + Quarks toast). Messages automation is documented but not tied to a catalog event authors recognize.
4. **Built graphs not in seed pack** — e.g. `buildDemoTaskPipelineWorkflowDefinition()` (`demo-workflow-definition-task-pipeline.ts`) implements `task.created` → shape payload → `switch_condition` → `publish_event` → notify; it is **not** in `DEMO_WORKFLOW_SEEDS` today.
5. **Time-based portfolio apps** — KB `review_due`, rental `rent.due` / `lease.expiring`, home `maintenance.due`, training `cert.expiring`, onboarding `task.overdue` are natural **schedule + query/notify** stories; **no demo uses cron schedules at all**.

Each item is a **concrete deliverable**: trigger(s), step palette used, seed/global workflow id, owner smoke, tests, and manifest/index updates when adding events.

## Suggested delivery order

1. **#1** task pipeline seed (unblocks Studio training for switch + publish).  
2. **#2** or **#4** (DM or rejection notify) — one people-channel story.  
3. **#11** one cron demo (proves scheduler in seeds).  
4. **#6–#9** pick **two** catalog apps you use in demos (KB + OKR recommended).  
5. **#17** only after owner call on game ↔ bus boundary.

## Out of scope (for now)

- New generic step kinds (`invoke_workflow`, outbound `http_request` production policy, arbitrary `emit_lab_event`) unless a P0–P2 graph is blocked without them.
- Replacing game **virtual bank** settlement in `match-service` with workflows without an explicit platform event design (#17).
- Duplicating CRM approval chains for every catalog app — prefer **one** integration + notify template per **vertical** (HR, facilities, learning).
