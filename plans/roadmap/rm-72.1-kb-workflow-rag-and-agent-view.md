## Problem

Human-authored KB articles (Forms Builder editor) store **`body` only**. `agent_view` stays `null` unless set via API or docs seed. Agents and RAG then fall back to long prose (`lab_kb_get`, `composeKbArticleIngestText`).

Seeded operating manual rows carry hand-authored `agent_view` in code; **team articles do not**.

## Goal

When a user publishes or materially updates an article, run **workflow-orchestrated automation** that:

1. **Generates** a structured `KbAgentView` from the human content.
2. **Persists** it on `kb_articles.agent_view`.
3. Lets the **existing** domain-event ingest refresh Chroma (`kb-chunks`) with agent markdown + body (no separate RAG invention step unless we add optional workflow action).

## Part A — Auto `agent_view` (primary)

### Trigger

| Event | When |
|-------|------|
| `app-knowledge-base.article.published` | First publish or draft → published |
| `app-knowledge-base.article.content_updated` | Re-save while `published` (optional: debounce / min body delta) |

Payload already carries `articleId` (and slug where published). Workflow Studio graphs listen on `/lab-events` like other automations.

### LLM call shape (games pattern, not Laboratory chat)

Mirror **catalog games** `agentMoveAsync` / `createPlatformAgentTurnDeps` (`src/shared/services/platform-llm-client.node.ts`, `platform-llm-completion`):

| Property | KB agent-view generation |
|----------|---------------------------|
| Runtime | Platform backend **:3000** (workflow step executor or dedicated service) |
| Memory | **None** — no Chroma, no `chat-memory`, no slot A pre-inject |
| Tools | Single **structural** tool, e.g. `kb_submit_agent_view`, Zod = `KbAgentView` (+ `summary` min length) |
| Input | System prompt: dual-audience rules from [KbAgentView](../../src/apps/knowledge-base/shared/types/index.ts) (no live ports in facts — use `liveSources`) + user payload: title, category, tags, slug, `app_id`, stripped `body` |
| Output | Parse tool args → validate → `UPDATE kb_articles SET agent_view = ?` |
| User | `actorUserId` from event, or configured **system user** for embed (`LAB_KB_RAG_EMBED_USER_ID` pattern) for provider resolution |

**Not** the Laboratory persona loop: no MCP tool fan-out, no session todo list, no user-visible chat transcript (unless product adds an audit log row).

### Persistence

- **Writer:** platform-side KB upsert (same validation as [knowledge-base `server.ts`](../../src/apps/knowledge-base/back-end/server.ts) `resolveAgentViewInput`) — or internal HTTP to KB app server with service credential.
- **Second `content_updated`:** ingest pipeline re-indexes; workflow should **not** loop infinitely (set `agentViewSource: 'workflow-llm'` metadata tag optional; or skip generate when `agent_view` already set unless `LAB_KB_AGENT_VIEW_REGENERATE=1` or body hash changed).

### Gating / safety

| Flag / rule | Purpose |
|-------------|---------|
| `LAB_KB_AGENT_VIEW_ON_PUBLISH=0` | Kill switch |
| Skip `docs:`-tagged rows | Seed reconcile owns agent_view (do not overwrite reconciled docs) |
| `includeUnpublished` | Never run on draft unless explicit admin workflow |
| Max body chars | Truncate for model context; store full structured view only from model output |
| Human-only articles | If model returns empty summary, leave `agent_view` null (fail open) |

### Suggested workflow graph (seeded demo)

1. **Trigger** — `article.published` OR `article.content_updated`
2. **Condition** — status published; tags lack `docs:`; optional body length > N
3. **Action (new)** — `generate_kb_agent_view` (platform step type)
4. **Action (existing patterns)** — `notify` author / admins on failure
5. *(Optional)* **rule_ref** — quality checks before publish (future)

## Part B — RAG re-index via workflow (deferred / optional)

Today **incremental ingest** already runs in `kb-chunks-ingest-on-domain-event.ts` on the same events. Part B is only needed when:

- Ingest is disabled (`LAB_KB_RAG_INGEST_ON_PUBLISH=0`) but workflows should batch embed.
- Surrounding automation (eval queue, Slack-style notify) should run **after** `agent_view` write.

Expose a workflow **action** that calls `KbChunksIndex.upsertArticle` / `buildIngestTextForKbArticle` with the **post-update** row. Coordinate with Part A ordering: **generate agent view → then ingest** (either inline pipeline after DB update, or workflow-only with pipeline ingest off).

Avoid **double-embed**: one owner of upsert per publish — pipeline XOR workflow action, documented in env.

## Out of scope (v1)

| Item | Why |
|------|-----|
| Agent-view editor in KB UI | API + workflow only; UI tab is rm-80+ |
| LLM rewriting human `body` | Only `agent_view` |
| Using Chroma to *generate* agent_view | Games pattern is explicit: no RAG on the generation call |
| Auto `app_id` inference | Optional later step; v1 uses column as-is |

## Acceptance (draft)

1. Publish a **non-docs** article with body only → within one workflow run, `agent_view` populated with valid JSON (`summary` + ≥1 pattern or gotcha per seed contract spirit).
2. `lab_kb_get(slug)` returns structured sections + full human body.
3. `npm run kb-rag:reindex` or event ingest: Chroma chunks include `## Agent summary` prefix.
4. CI: unit test for Zod tool parse + mock platform LLM; workflow integration test with fixture event.
5. Docs seed articles unchanged when user toggles feature on.
