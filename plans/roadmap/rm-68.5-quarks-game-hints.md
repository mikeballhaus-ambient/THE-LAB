# rm-68.5 — Quarks game hints (UI overlays)

**Status:** ✅ Closed (2026-11-13) · [tracker](../../rm-68.5/IMPLEMENTATION-TRACKER.md) · [closeout](../../docs/archive/programmes/rm-68.5/EXECUTOR-CLOSEOUT.md)  
**Roadmap:** [docs/roadmap.md](../../docs/roadmap.md) (rm-68.5)

## Goal

Give Quarks a **spend sink** beyond frame wagers: players optionally purchase **in-game UI hints** (visual assistance on their turn), debited via the lab virtual bank. Catalog games and solo titles (e.g. solitaire) share a small platform contract; each app supplies **what** to reveal after purchase.

## In scope

| Item | Notes |
|------|--------|
| **Human UI overlay hints** | e.g. billiards shot-path preview while aiming (`computeBilliardsShotHintPaths` / `showShotPathHints` in `BilliardsTable.vue`) — gated off by default, unlocked per shot or per turn after Quarks purchase |
| **Platform hint purchase API** | App-server route + platform `virtual-bank/adjust` with idempotent `sourceRef`; new reason code e.g. `hint_purchase` |
| **Shared client composable** | Balance check, purchase ack, unlock UI flag for one bounded reveal |
| **Per-app hint SKUs** | Manifest or app config: cost, eligibility (whose turn, phase), copy |
| **Solitaire + catalog games** | Same contract; solo = pure sink (no PvP fairness rules) |

## Explicitly out of scope (do not conflate)

| Item | Why |
|------|-----|
| **Sidecar / Lab Assistant table talk** | Banter pipeline (`lab-assistant-banter`, agent AIM HINTS in prompts) — separate product surface |
| **LLM agent move hints** | `billiards-agent-aim-hints.ts`, search advisory in user prompts — opponent intelligence only |
| **Billiards dev tooling** | `BILLIARDS_SHOW_DEV_TOOLS`, collider wireframe, dev grid — internal tuning only |
| **Autoplay or engine-best-move** | Violates vs–Lab Assistant policy; hints are **bounded UI reveals**, not submitted moves |

## Product rules (draft)

1. **One purchase → one bounded reveal** (e.g. overlay until shot fires, or one turn’s highlight).
2. **PvP:** hints only on **your** turn; no hidden-information leaks (fog-of-war games).
3. **`rules.practice`:** free hints or simulated UI (align with poker/blackjack practice policy).
4. **Pricing:** anchor below frame-wager tiers; tune per archetype (geometry vs discrete move).

## Suggested phasing (implementation)

1. **Platform skeleton** — ledger reason, purchase route pattern, `useLabGameHint` (or shared kit name), tests.
2. **Billiards pilot** — gate `showShotPathHints`; lobby/chip UX; owner verify.
3. **Second archetype** — discrete-move game (e.g. connect-four or solitaire).
4. **Catalog rollout** — matrix of hint types per app; docs in `docs/platform/lab-quarks-hints.md`.
