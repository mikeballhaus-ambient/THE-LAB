# rm-68.4 — Lab shell UI automation (workspace, catalog chrome, launch)

**Status:** ✅ Closed 2026-11-12 — [EXECUTOR-CLOSEOUT.md](../../docs/archive/programmes/rm-68.4/EXECUTOR-CLOSEOUT.md) · [tracker](../../rm-68.4/IMPLEMENTATION-TRACKER.md)  
**Roadmap:** [docs/roadmap.md](../../docs/roadmap.md) (rm-68.4)  
**Parent theme:** [rm-68](./rm-68-agent-app-awareness.md) — agents operate the Lab the same way humans do; **UI automation is the control plane**.  
**Builds on:** [rm-68.3](./rm-68.3-ui-automation-discovery-refactor.md) (`searchPattern`, `elementRef`, context profiles), [rm-68.1](./rm-68.1-sidecar-shell-features-awareness.md) (shell overlays), [lab-ui-automation.md](../../docs/platform/lab-ui-automation.md)

## Constraint (product)

**No MCP tools for app launch or teardown.** Agents must **launch**, **switch**, **split**, and **close** apps the same way users do — `ui_automation_discover_elements` + `ui_automation_element_action` on catalog and workspace chrome only. Do not add or document `lab_shell_launch_app`-style shortcuts in this programme unless product explicitly reverses this.

## Problem

Catalog **launch** grew a bespoke discover pipeline (launch-only filtering, registry appendix, search priming, card-title fallbacks). That does **not** generalize to the rest of the shell:

- Open **app launcher** / **running apps** rails  
- **Switch active tab** to a running app  
- **Split / tabs / form designer** layout modes  
- Minimize / restore / close tab  

Today many chrome controls are **visible to humans** but **invisible to discover** under `app-list-container` rules, or lack stable **`data-lab-shell-action`** / **`uiRole`** contracts. Agents cannot reliably do “anything the user could click.”

## Goal

One **lab shell automation contract** across catalog, workspace, and quick-nav chrome so Sidecar agents can complete arbitrary shell tasks via **discover → `elementRef` → act**, without a new special case per request type.

**Launch stays first-class** — humans also cannot launch an app that is not reachable in the UI. Agents use the **same two launch paths**:

| Shell state | How the human finds the app | Agent playbook |
|-------------|----------------------------|----------------|
| **No apps running** (apps home / full grid) | **Search apps…** — any enabled app appears in the filtered grid, including apps beyond the **8-per-section** preview | `element_action` `setValue` on `input.lab-catalog-search` (or discover auto-prime) → `searchPattern` + `catalog-launch` |
| **≥1 app running** (compact launcher) | **App launcher sidebar** lists **all** launchable apps (nothing hidden by section preview); already-running apps show **Close** / teardown, not duplicate launch | `contextArea` `lab-app-catalog-sidebar`; expand `lab-catalog-sidebar-rail` if collapsed; `searchPattern` on display name / registry id |

Registry appendix in Sidecar remains the **authoritative name/id list**; DOM paths differ by shell state, not by agent-only APIs.

## Shell control vocabulary (target)

| `uiRole` (examples) | Region (`contextArea`) | Examples |
|---------------------|------------------------|----------|
| `catalog-launch` | `app-list-container`, `lab-app-catalog-sidebar` | Launch / Close on app row |
| `catalog-chrome` | `app-list-container` | Search, tag chips, carousel nav, **Open app launcher** |
| `shell-rail` | `app-list-container` | Running-apps rail expand / restore |
| `workspace-tab` | `lab-workspace-tabbar`, `app-view-container` | Switch focused app |
| `workspace-layout` | `lab-workspace-tabbar` | Tabs / Split ↔ / Form designer |
| `workspace-chrome` | `lab-workspace-tabbar` | Minimize all, dependency toggle |
| (existing) | overlays | Settings, Messages, Quarks — rm-68.1 |

**Attributes:** `data-lab-shell-action`, optional `data-lab-target-app-id` / `data-app-id`, `aria-label` aligned with [lab-shell-naming.ts](../../src/shared/constants/lab-shell-naming.ts).

**Discover:** context profiles per region; **intent** or profile slices (`chrome` | `launch` | `workspace` | `in-app`) — avoid “catalog context = launch-only OR toolbar-only” as the only modes.

## In scope

1. **Tagging** — `AppViewLayout.vue` tab bar, layout pills, minimize; `LabAppCatalogSidebar.vue` + `LabRunningAppsRail.vue` rails; catalog search (already partially tagged).
2. **Discover handler** — profiles + roles for new regions; refactor catalog branch so **chrome** and **launch** are separate discover intents; workspace tab match by app name/id on tab or `data-lab-target-app-id`.
3. **Sidecar appendix** — `workspaceLayout.mode`, active tab id/name, launch playbook table (grid+search vs sidebar); shell chrome hints (not launch-only prose).
4. **Docs** — extend [lab-ui-automation.md](../../docs/platform/lab-ui-automation.md) with shell map; [lab-sidecar.md](../../docs/platform/lab-sidecar.md) “workspace verbs”.
5. **Tests** — discover unit tests for tab/layout/rail; prompt tests for new appendix fields.
6. **Simplify** — remove or demote launch-only crutches once tagging + profiles cover hero/grid/sidebar (keep card `data-appname` as defense in depth).

## Out of scope

- **`lab_shell_launch_app`** / **`app_management` teardown** MCP shortcuts — explicitly **not** in scope; UI automation is the only control plane for launch/teardown.
- In-app product UI beyond existing rm-68.2 record/catalog patterns.
- Full Laboratory-only flows (remain rm-67.8 / future).

## Acceptance criteria

1. **Launch (no apps running):** Sidecar agent launches an app **not** in the first 8 of a category using **search + discover + click** only (e.g. 9th productivity app or Workflow Studio via search).
2. **Launch (apps running):** Agent launches a **second** app via **app launcher sidebar** without user manual expand, when rail was collapsed.
3. **Switch tab:** User asks “switch to CRM” with CRM + another app open → agent focuses CRM via workspace tab discover + click.
4. **Split:** User asks “split view” with ≥2 apps → agent clicks **Split ↔** and split panes visible.
5. **Rails:** User asks “open the app launcher” / “show running apps” → discover returns rail control; click expands panel.
6. `npm run test:pipeline` green; owner spot-check documented in tracker.
7. Roadmap **rm-68.4** closed with closeout under `docs/archive/programmes/rm-68.4/`.
