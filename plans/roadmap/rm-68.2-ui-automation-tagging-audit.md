## Problem

Sidecar and Laboratory agents use `ui_automation_discover_elements` + `ui_automation_element_action`. Discovery fails or mis-clicks when:

- List **edit/delete** controls reuse the same `generateUniqueId('…-edit')` inside `v-for` (duplicate DOM ids).
- Icon-only row actions lack **`data-lab-record-id` / `data-lab-record-name` / `data-lab-record-action`** (name not matchable via `searchPattern`).
- **`contextArea`** in app system instructions does not match mounted app shell classes.
- Forms Builder **save/cancel** bars lack record-scoped action attrs when hosted in integration dialogs.
- Per-app instructions omit stable selectors agents should prefer over guessed `#id`s.

Nearly all **non-game** catalog apps share the same master-list + integration-dialog pattern; fixes should use the **shared contract**, not one-off workflow patches.

## Goal

Every catalog host and platform list surface (Settings tables, Workflow Studio, rules, approvals, …) exposes **consistent, auditable** automation hooks so Sidecar can find the right row action on the first discover pass.

## Shared contract (reference implementation)

| Piece | Location |
|-------|----------|
| Data attrs + search helper | `src/shared/constants/lab-record-automation.ts` |
| Edit/delete cluster | `src/shared/ui/LabRecordRowActions.vue` |
| Discovery / `target` | `UIAutomationHandler` + MCP discover description |
| Catalog doc | `docs/apps/catalog-workspace-ui-pattern.md` § UI automation |

Row wrappers: `data-catalog-primary-id` + optional `data-lab-record-name`.  
Buttons: `labRecordActionRootAttrs()` or `LabRecordRowActions`.  
Ids: `generateUniqueId(\`<prefix>-<action>-${recordId}\`)` — never bare edit prefix in loops.

## In scope

| Area | Audit actions |
|------|----------------|
| **Catalog apps** (`src/apps/*`, non-game) | Master-list pencil/trash/create; integration primary actions; instructions ↔ `contextArea` + selector table |
| **Platform settings** | Workflows (done baseline), rules, personas tables, approvals, chart connector lists, KB admin, etc. |
| **App system instructions** | Align FAQ / automation bullets with real DOM (`data-appname`, record attrs, dialog `contextArea`) |
| **Optional gate** | Script or ESLint heuristic for `generateUniqueId('…-edit')` / `…-delete` without `${id}` inside `#body` / `v-for` templates (stretch) |

## Out of scope

- **Turn-based / arcade games** — board-specific automation remains game-kit / smoke only unless a list lobby needs record attrs.
- **rm-68** prompt-layer rewrites (inventory, sysMsg conflicts) — queued after this audit.
- Replacing MCP/REST with UI automation for every Settings control.

## Acceptance criteria

1. Inventory document (tracker) lists each app/surface: **pass**, **fixed**, or **exempt** with reason.
2. All **catalog integration hosts** use record action attrs on primary edit/delete (component or helper).
3. High-traffic platform lists (workflows, rules, catalog demo hosts) verified via discover + one click path in owner spot-check.
4. `npm run test:pipeline` green; new CI coverage for automation helpers where added.
5. Roadmap **rm-68.2** closed; **rm-68.3** unblocked.

## Phasing (suggested)

1. **Inventory** — grep + manual pass; classify defects (duplicate id, missing attrs, wrong contextArea, instruction drift).
2. **Platform + reference apps** — CRM, polls-surveys (attrs on existing per-id buttons), task-list, help-desk, workflow studio shell.
3. **Long tail catalog** — batch by integration host list (`CATALOG_HOST_APP_IDS` / manifests).
4. **Instructions sync** — update `app-instructions/*.ts` and shared automation guidance in MCP tool description.
