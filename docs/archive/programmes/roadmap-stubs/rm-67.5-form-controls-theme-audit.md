# rm-67.5 — Form controls & buttons theme-token audit

**Status:** 🔄 In progress (opened 2026-11-11)  
**Roadmap:** [docs/roadmap.md](../../docs/roadmap.md) (rm-67.5)  
**Related:** [rm-49](../../docs/roadmap.md) (platform themes v1), [rm-67](./rm-67-tailwind-css-audit.md) (Vue `<style>` audit, in progress)  
**Opened:** 2026-11-11

## Problem

Interactive chrome often bypasses the **theme token contract**: PrimeVue global PT, bespoke CSS classes (`lab-chat-micro-button`, composer chips), and **derived aliases** set in `applyLabTheme()` (`--lab-text`, `--lab-form-control-bg`, chat tab surfaces, …). Light presets still ship **dark-first** values in SQLite seed tokens (e.g. `chat-tab-active-bg`, solid `button-bg` on micro-actions). Gaps show up as low-contrast labels, “dark mode” buttons in light shell, or utilities that reference **undefined** `--lab-*` aliases.

**Goal:** Systematic audit of **forms, buttons, selects, toggles, tabs, and composer/sidecar actions** so every surface uses **resolved theme tokens** (preset keys + derived aliases), with **mode-aware** behavior where presets are shared across light/dark.

**Out of scope:** Game board geometry, chart canvas libs, third-party teleports without token hooks (document exceptions).

---

## Acceptance criteria

1. **Inventory** — List controls/button patterns (PrimeVue + native + custom classes) with token source per pattern; flag hard-coded `slate-*`, missing aliases, and preset keys that read dark in light mode.
2. **Contract** — Document required derived aliases in [platform-theming.md](../../docs/platform/platform-theming.md) (or compact table in this plan); `applyLabTheme` and `@theme` stay in sync.
3. **Fix pass** — Mode-aware derived tokens or PT/CSS updates; no new fixed hex in component scoped CSS.
4. **Verify** — Spot-check **4 presets** (2 light / 2 dark): Laboratory composer, Sidecar, Settings → Themes, one catalog form dialog; `npm run test:path "lab-theme"` green.
5. **Closeout** — Roadmap rm-67.5 → Completed; handoff note if bundled with rm-67 programme.

## Suggested work order

1. Extend discovery script or checklist from rm-67 inventory (**PrimeVue usage + `lab-*` button utilities**).
2. Normalize **light** chat/workspace tab + composer actions (pattern: derived tokens in `applyLabTheme`, `.app-light` only when PT cannot express).
3. Audit **Select / InputText / ToggleSwitch / SelectButton / Button** PT vs `lab-settings-field` / `lab-form-runtime` overrides.
4. Sweep platform apps for `text-lab-text-primary` / orphan utilities → canonical `text-lab-general-text` or registered aliases.
5. Preset seed review: whether `chat-tab-*` and composer label tokens need light-preset-specific values vs runtime derivation only.
