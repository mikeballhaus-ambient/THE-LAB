## Problem

Consecutive MCP tool results in **Laboratory** render as one summary row per call (`Todo List — Success`, …). Detail bodies are already collapsed, but **many rows** between the user turn and the assistant reply distract from the conversation.

## Goal

One **primary disclosure** per **tool run** — label like **“Agent is using tools (N)”** — **collapsed by default**. Expanded: list each call (existing row + optional detail expand). Preserve access to full `formatMcpToolResult` output for debugging.

---

## Grouping rules (product contract)

Grouping is by **contiguous tool-result messages** in the session transcript, not by tool family or persona.

| Message sequence | UI |
|------------------|-----|
| Adjacent `role: system` + `systemLog.isResult === true` | **Single batch** — one outer toggle, N inner rows |
| User, assistant (visible text), followup, thinking-only, or `system` log that is **not** a tool result | **Break** — ends current batch; next tool result starts a **new** batch |
| Todo ×3 then `read_file` ×2 then `persona_manager` ×1, **no break between** | **One** toggle **(6)** — tool *type* does not split batches |
| Todo ×3 → **assistant reply** → user message → `read_file` ×2 | **Two** toggles — one after first user turn, one after second |

So: **todo list calls followed immediately by other tool calls = same toggle.**  
**Separate toggle only when something non–tool-result sits between them** (usually the assistant’s answer or a new user message).

Edge cases (document in tracker):

- Streaming assistant text **between** tools in one provider turn — if the backend inserts assistant chunks between tool logs, batches split at those chunks (match transcript fidelity).
- Single tool call — batch of 1, same UX (toggle shows “(1)”).
- Failed vs success — aggregate label may show mixed status icon or “N succeeded, M failed” when expanded header is closed.

## Scope

| Area | Paths |
|------|--------|
| Grouping | New `groupChatToolResultBatches()` (or extend `merge-persisted-tool-result-messages` patterns) in `src/shared/` |
| Laboratory UI | `MessagesView.vue`, `useMessagesView.ts`, `lab-chat-shell.css` |

| Tests | CI unit tests on grouping from fixture message arrays |
| Settings (optional v2) | Session setting: always expand tool batches / show legacy per-row |

**Out of scope:** Changing MCP execution, persisting merged messages to Dexie (display-layer only), tool formatter content.
