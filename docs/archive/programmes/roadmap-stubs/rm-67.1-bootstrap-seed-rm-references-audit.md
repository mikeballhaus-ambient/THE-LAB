# rm-67.1 — Bootstrap / demo seed copy audit (no roadmap ids in product data)

**Status:** ✅ Completed (2026-11-11)  
**Roadmap:** [docs/roadmap.md](../../docs/roadmap.md) (rm-67.1)  
**Related:** [rm-64](../../docs/roadmap.md) (integrations — many seeds born here), [rm-48.5](../../docs/roadmap.md) (App Demo Data)  
**Opened:** 2026-11-11

## Problem

Bootstrap, demo, and integration **seed paths** sometimes embed internal programme ids such as `rm-64` in **user-visible** strings (form names/descriptions, demo record titles, default help text persisted to SQLite or app DBs). Example reported in Forms Builder: **Edit HomeAsset** with description `Stub form for home-asset.edit.dialog (rm-64)`.

Roadmap ids belong in `plans/`, `docs/roadmap.md`, agent handoffs, and code **comments** — not in seeded product copy shown in the lab UI or passed to integrations.

**Goal:** Inventory seed and provisioner output; remove or rewrite `rm-*` references in persisted user-facing fields; add a lightweight guard so new seeds do not reintroduce them.

---

## Scope

| Area | Paths / artifacts |
|------|-------------------|
| Integration form stubs | `src/backend/lab-integrations/lab-integrations-form-stub-provisioner.ts` (known `(rm-64)` in `description`) |
| Repository `initialize()` / bootstrap | `src/backend/db/**` seeds (apps, personas, commands, integration bindings, workflow demos, etc.) |
| Demo data tiers | App demo packs, `export:demo-workflows` / apply scripts, Settings → App Demo Data restore paths |
| Per-app DB seeds | Migrations and seed SQL/TS under `src/apps/**/db/` and shared schema templates when run on boot |
| Forms Builder persisted schemas | Rows created at runtime by provisioners (may need one-time cleanup or re-provision after fix) |

**In scope for audit:** string fields that surface in UI (names, titles, descriptions, labels, toast copy in seeds, default `helpText`, form `description`, chart metadata, workflow node labels in **demo** graphs).

**Out of scope:** Agent-only surfaces (`app_system_instructions`, `plans/`, `docs/`, JSDoc, commit messages). Those may keep `rm-*` for traceability.

---

## Acceptance criteria

1. **Inventory** — Grep or script across `src/backend/db`, `src/backend/lab-integrations`, demo export scripts, and app seed modules for `rm-\d` in string literals destined for DB/user UI; attach manifest to this plan or `plans/rm-67.1/` when opened.
2. **Policy** — One paragraph in [app-system-instructions.md](../../docs/platform/app-system-instructions.md) or demo-data ops doc: no roadmap ids in seeded user copy; prefer domain language (“integration stub”, “demo workflow”).
3. **Fix pass** — Rewrite affected seeds/provisioners (e.g. stub descriptions without `(rm-64)`); migrate existing DBs idempotently where boot does not overwrite (document “re-apply demo pack” or SQL one-liner for owners).
4. **Guard** — Optional CI/regression test: fail if new seed strings in allowlisted paths match `\brm-\d+(\.\d+)?\b` outside excluded dirs (`app-instructions`, `plans`, `docs`).
5. **Verify** — Forms Builder: open a catalog stub form (e.g. home-maintenance home-asset edit); description has no `rm-`; spot-check Settings demo restore; `npm run verify:integration-seeds` and `test:ci` green if guard added.
6. **Closeout** — Roadmap rm-67.1 → Completed.
