**Opened:** 2026-11-11

## Problem

Large parts of the lab still use **fixed Tailwind palette utilities** (`text-white`, `text-mist-*`, `text-slate-*`, `bg-slate-*`, `border-cyan-*`, raw hex in scoped CSS) that were authored for **dark chrome**. On **light presets**, copy disappears, borders vanish, and surfaces read as the wrong mode. Platform contract is **`lab-*` utilities** and **`--lab-*` CSS variables** set by `applyLabTheme()` — not ad-hoc `slate` / `mist` / literal colors on product UI.

Recent examples:
- **Form Designer — metadata / connectors (fixed ad hoc 2026-11-11):** Link connector sidebar, form properties card, Form actions settings → token pass; **deferred to rm-67.2:** component library, design canvas, grid cells, containers (`src/apps/lab-formsbuilder/front-end/components/form-designer/**` — pervasive `bg-slate-*`, `text-mist-*`, `border-mist-*`).
- Same app before fix: connector header `text-white`, `lab-app-list-*` without token CSS, Form actions `text-mist-*` labels.

**Goal:** Repo-wide audit and conversion of **user-visible** color usage to theme tokens; define allowlists/exemptions; optional lint or CI grep gate to prevent regression.

**Out of scope / sibling work:** Seed strings with `rm-*` ids → **rm-67.1**; control-specific PT contract depth → **rm-67.5**; removing scoped blocks for layout → **rm-67**.

## Acceptance criteria

1. **Inventory** — Machine-assisted scan (extend rm-67 inventory or new script) for patterns: `mist-`, `slate-` (non-token), `text-white` on non-overlay surfaces, `cyan-`/`sky-` chrome, `#` / `rgb(` in Vue/CSS under `src/dashboard`, `src/shared`, `src/apps`, `src/assets/styles`. Output: file list + counts by bucket (shell / shared / apps).
2. **Policy** — Short section in [platform-theming.md](../../docs/platform/platform-theming.md): allowed patterns (`text-lab-general-text`, `bg-lab-general-bg-muted`, `var(--lab-*)`), banned patterns for new code, when `color-mix` with tokens is preferred.
3. **Fix waves** — Prioritized passes: (a) shell + settings, (b) shared integration/form surfaces, (c) catalog apps by portfolio tier, (d) games lobby/play chrome. Each wave: light + dark spot-check on **≥2 presets** each.
4. **Regression guard** — Optional ESLint custom rule or `npm run verify:theme-colors` (grep allowlist) on new/changed Vue under `src/apps` and dashboard; not required for legacy debt in first PR but documented.
5. **Verify** — Owner checklist: Laboratory, Sidecar, Settings (Themes), one catalog host, Forms Builder designer (connector list + form actions), one game lobby; `npm run test:path "lab-theme"` green.
6. **Closeout** — Roadmap rm-67.2 → Completed; overlap with rm-67.5 documented (controls subset may close first).
